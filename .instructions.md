# Flutter / GetX Development Instructions

## GetX startup and routing rules
- Always use GetMaterialApp with a valid initialRoute and a matching entry in getPages.
- Do not use Get.find() in field initializers or during widget construction before the controller has been registered.
- Prefer registering controllers in Bindings and using Get.put()/Get.lazyPut() there.
- If a controller must be accessed from a view, use a getter that calls Get.find() lazily, or inject it through a binding/controller pattern.
- Avoid calling Get.find() inside the constructor of a widget or view before the binding has run.
- Make sure the initial route page can be built without throwing exceptions.
- Keep the first screen simple and avoid heavy async work that blocks the first frame.
- If a controller uses async initialization, make sure it does not crash the UI when the data is unavailable.
- Never assume that a release build will be fine if the app crashes during first render; debug and release both need a safe startup path.

## Common blank-screen causes
- A controller is accessed before it is registered.
- A view calls Get.find() too early during construction.
- A binding or controller throws in onInit/onReady.
- A late variable or null assertion (!) fails during startup.
- SharedPreferences or other async initialization throws before the screen renders.

## Preferred pattern
- Use GetMaterialApp with initialRoute and getPages.
- Define routes in AppPages.routes.
- Register dependencies in bindings.
- Let the first page be a simple shell page if needed, then build the real content after initialization.
